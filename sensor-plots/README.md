# ФабЛаб: графики датчиков на Rust

Самостоятельное оконное приложение: температура ×3 (°C), давление ×3 (Па), влажность ×3 (%RH), VOC Index ×2 и один GP2Y1010AU0F (сырой ADC и напряжение в вольтах). Концентрация пыли не рассчитывается.

Программа читает только GET-эндпоинты FastAPI. Ничего не переключает, COM-порт не открывает. Сначала запустите соответствующий FastAPI-сервис, подключённый к хабу; приложению нужен его HTTP-адрес.

## Windows

Установите [Rust через rustup](https://rust-lang.org/tools/install/) и C++ Build Tools для MSVC (Visual Studio Build Tools, компонент Desktop development with C++). Проверенная версия Rust — 1.91.1 или новее.

Из корня `tjc-commutator` в PowerShell:

```powershell
cd "sensor-plots"
cargo run --release --locked
```

По умолчанию сервер: `http://127.0.0.1:8000`. Чтобы изменить адрес/частоту:

```powershell
cargo run --release --locked -- --url http://192.168.1.20:8000 --interval 2 --timeout 45 --points 1800
```

Собранный файл: `target\release\fablab-sensor-plots.exe`. Его можно запускать без Cargo с теми же аргументами. Для первой сборки нужен интернет; версии зависимостей фиксируются в Cargo.lock.

## Как читать окно

Каждый канал показан отдельно. Аналоговые датчики имеют два отдельных графика: ADC и V, чтобы не смешивать единицы на общей оси. Время X — секунды с момента запуска приложения, момент получения HTTP-ответа, не время измерения датчика.

Над графиками отображаются `valid`, `fresh`, `age_ms`, `received_at` и время с последнего HTTP-ответа. `fresh=false` не является ошибкой: флаг глобальный, его мог прочитать другой клиент. Поэтому каждый валидный HTTP-снимок, включая кэш, добавляется на ось получения ответа; кэш явно помечен `cached`. Это не подсчёт уникальных аппаратных измерений, и одинаковые значения могут повторяться.

`--max-age-ms` (по умолчанию 10000 мс; диапазон 0..65533) — порог **визуализации**, не новый аппаратный контракт. При возрасте выше порога создаётся разрыв и показывается `stale`. Насыщенный возраст `age_ms=65534` всегда считается устаревшим: истинный возраст может быть гораздо больше. `valid=false`, HTTP-ошибка или некорректный JSON тоже создают разрыв, а не точку с вымышленным нулём. На графике остаётся предыдущая история, поэтому при ошибке смотрите статус канала, а не только последнюю линию.

Колесо мыши — масштабирование, перетаскивание — панорама, двойной щелчок — автоподбор масштаба. При перезапуске история очищается; запись на диск пока не реализована.

## Опрос и ограничения

HTTP выполняется в отдельном рабочем потоке, интерфейс не ждёт оборудование. Запросы строго последовательные, одновременно активен максимум один GET: это учитывает общую очередь сервера. `--interval` — пауза **после полного прохода** по датчикам, а не гарантированный период для каждого канала. Медленная система увеличивает период; повторные попытки происходят в следующем проходе. Не запускайте одновременно много окон с коротким интервалом.

`--timeout` задаёт полный таймаут одного HTTP-запроса; подключение ограничено 5 с. Перенаправления запрещены. Ответ ограничен 64 KiB. При закрытии окна новые запросы прекращаются; уже отправленный GET может завершиться на сервере. История ограничена `--points` точками на каждую величину (по умолчанию 1800), очередь обновлений интерфейса — 64 события.

Это средство наблюдения, не аварийная автоматика и не измеритель концентрации. Автоматическое обнаружение URL, переключение теплицы, управление актуаторами и экспорт данных не предусмотрены. Нужна Windows с графическим окружением/OpenGL; на Linux нужны X11 и системные графические библиотеки.

## Проверка кода

Аппаратные проверки по частям и в связке: [руководство TESTING.md](../docs/TESTING.md).

```powershell
cargo check --locked
cargo test --locked
cargo test --locked --no-default-features
```

Последняя команда проверяет модель JSON и историю без графического окружения. Тесты проверяют отрицательную температуру, quality-поля, аналоговый ответ с/без индекса, неверные единицы/JSON/ошибки, ограничение истории и разрывы. Реальный вывод графиков и работу с вашей аппаратурой нужно проверить на рабочем компьютере.

Библиотеки: [eframe 0.31.1](https://docs.rs/eframe/0.31.1/eframe/), [egui_plot 0.32.1](https://docs.rs/egui_plot/0.32.1/egui_plot/), [reqwest blocking](https://docs.rs/reqwest/latest/reqwest/blocking/). Оба Cargo-проекта независимы; общих относительных зависимостей между папками нет.
