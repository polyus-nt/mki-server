# Химреактор: графики датчиков на Rust

> Сервер использует SimpleBus 115200 с согласованием от хаба, без секундных пауз.
> Приложение использует прежний HTTP API. Обновите сервер и все платы МС-ТЮК;
> Arduino TEST Serial остаётся 9600. Пауза --interval после полного обхода сохранена.

Самостоятельное оконное приложение: температура ×2 (°C), давление ×2 (Па), влажность ×2 (%RH), MQ-2 ×2 (сырой ADC и напряжение в вольтах). Концентрация газа не рассчитывается.

Программа строит графики и позволяет вручную отправлять команды через FastAPI. COM-порт не открывает. Сначала запустите соответствующий FastAPI-сервис, подключённый к хабу; приложению нужен его HTTP-адрес.

## Windows

Установите [Rust через rustup](https://rust-lang.org/tools/install/) и C++ Build Tools для MSVC (Visual Studio Build Tools, компонент Desktop development with C++). Проверенная версия Rust — 1.91.1 или новее.

Из корня `tjc-commutator` в PowerShell:

```powershell
cd "chem-reactor-теплица\sensor-plots"
cargo run --release --locked
```

По умолчанию сервер: `http://127.0.0.1:8001`. Чтобы изменить адрес/частоту:

```powershell
cargo run --release --locked -- --url http://192.168.1.20:8001 --interval 2 --timeout 45 --points 1800
```

Собранный файл: `target\release\chem-sensor-plots.exe`. Его можно запускать без Cargo с теми же аргументами. Для первой сборки нужен интернет; версии зависимостей фиксируются в Cargo.lock.

## Как читать окно

Каждый канал показан отдельно. Аналоговые датчики имеют два отдельных графика: ADC и V, чтобы не смешивать единицы на общей оси. Время X — секунды с момента запуска приложения, момент получения HTTP-ответа, не время измерения датчика.

Над графиками отображаются `valid`, `fresh`, `age_ms`, `received_at` и время с последнего HTTP-ответа. `fresh=false` не является ошибкой: флаг глобальный, его мог прочитать другой клиент. Поэтому каждый валидный HTTP-снимок, включая кэш, добавляется на ось получения ответа; кэш явно помечен `cached`. Это не подсчёт уникальных аппаратных измерений, и одинаковые значения могут повторяться.

`--max-age-ms` (по умолчанию 10000 мс; диапазон 0..65533) — порог **визуализации**, не новый аппаратный контракт. При возрасте выше порога создаётся разрыв и показывается `stale`. Насыщенный возраст `age_ms=65534` всегда считается устаревшим: истинный возраст может быть гораздо больше. `valid=false`, HTTP-ошибка или некорректный JSON тоже создают разрыв, а не точку с вымышленным нулём. На графике остаётся предыдущая история, поэтому при ошибке смотрите статус канала, а не только последнюю линию.

Колесо мыши — масштабирование, перетаскивание — панорама, двойной щелчок — автоподбор масштаба. При перезапуске история очищается; запись на диск пока не реализована.


## Ручные команды на платы

Внизу окна есть панель **«Команды на платы»**. Введите команду и нажмите **«Отправить»** или Enter. Справка раскрывается прямо в панели; команда `help` тоже показывает её, без обращения к плате. Показаны HTTP-метод, путь, статус и JSON ответа, включая фактически применённые значения и аппаратные ошибки.

Примеры для химреактора:

```text
temp 0
get_pwm 1
set_pwm 1 128
set_door_lock 0
lock
set_door_lock 1
set_relay_level 4
relay
set_relay_level 0
```

`set_door_lock 0` открывает обе двери (общий выход), `set_door_lock 1` закрывает обе. Индекса замка нет. `set_relay_level` принимает 0..10, 0 выключает релейный вентилятор. Режимов отказа, пылесоса, VOC и пыли в этой программе нет.

Чтения: `temp`, `pressure`, `humidity`, `gas`, `door`, `pwm`, `rpm` с индексом 0..1; `lock`, `relay`, `capabilities`, `probe` без индекса. `set_pwm idx pwm`: idx 0..1, PWM 0..255.

Для чтений также работают API-имена `get_temp`, `get_pressure`, `get_humidity`, `get_door_state`, `get_pwm`, `get_rpm`, `get_door_lock` и `get_gas`, `get_relay_level`. Аргументы разделяются пробелами (не скобками и запятыми). Несуществующие команды и неверные диапазоны отклоняются **до отправки**.

**Осторожно: записи реально управляют оборудованием.** Автоматических команд записи при запуске нет. Административные методы доступны без токенов, как в существующем сервисе. Это не проверка доступа: не публикуйте сервис в недоверенной сети. Открытие замка через API не является двухсекундным импульсом кнопки: дверь остаётся открытой до следующего управляющего действия.

Одна ручная команда ожидает/выполняется за раз; кнопка отправки до ответа заблокирована. Команда проходит через общий рабочий поток **между отдельными чтениями датчиков** или во время паузы, а затем через FIFO сервера. Уже выполняющийся запрос не прерывается. В журнале хранятся последние 20 команд, до 8000 символов ответа на каждую.

Записи **не повторяются автоматически**. При таймауте/обрыве соединения команда уже могла исполниться: проверьте состояние отдельным чтением перед повтором. Закрытие окна не отменяет уже отправленный HTTP-запрос; неотправленные команды из локальной очереди не исполняются.

## Опрос и ограничения

HTTP выполняется в отдельном рабочем потоке, интерфейс не ждёт оборудование. Запросы строго последовательные, одновременно активен максимум один HTTP-запрос (GET или POST): это учитывает общую очередь сервера. `--interval` — пауза **после полного прохода** по датчикам, а не гарантированный период для каждого канала. Медленная система увеличивает период; повторные чтения датчиков происходят в следующем проходе; ручные команды не повторяются. Не запускайте одновременно много окон с коротким интервалом.

`--timeout` задаёт полный таймаут одного HTTP-запроса; подключение ограничено 5 с. Перенаправления запрещены. Ответ ограничен 64 KiB. При закрытии окна новые запросы прекращаются; уже отправленный запрос может завершиться на сервере. История ограничена `--points` точками на каждую величину (по умолчанию 1800), очередь обновлений интерфейса — 64 события.

Это средство наблюдения и ручного управления, не аварийная автоматика и не измеритель концентрации. Автоматическое обнаружение URL, переключение теплицы и экспорт данных не предусмотрены. Нужна Windows с графическим окружением/OpenGL; на Linux нужны X11 и системные графические библиотеки.

## Проверка кода

Аппаратные проверки по частям и в связке: [руководство TESTING.md](../../docs/TESTING.md).

```powershell
cargo check --locked
cargo test --locked
cargo test --locked --no-default-features
```

Последняя команда проверяет модель JSON, историю и разбор команд без графического окружения. Полный `cargo test` дополнительно проверяет отправку POST/GET на локальный HTTP-сервер, JSON-тело, отображение фактического PWM и HTTP-ошибок, лимит ответа. Тесты проверяют отрицательную температуру, quality-поля, аналоговый ответ с/без индекса, неверные единицы/JSON/ошибки, ограничение истории и разрывы. Реальный вывод графиков и работу с вашей аппаратурой нужно проверить на рабочем компьютере.

Библиотеки: [eframe 0.31.1](https://docs.rs/eframe/0.31.1/eframe/), [egui_plot 0.32.1](https://docs.rs/egui_plot/0.32.1/egui_plot/), [reqwest blocking](https://docs.rs/reqwest/latest/reqwest/blocking/). Оба Cargo-проекта независимы; общих относительных зависимостей между папками нет.
