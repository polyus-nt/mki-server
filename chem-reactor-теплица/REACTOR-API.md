# API реактора в составе теплицы-химреактора

Сервис: `http://127.0.0.1:8001`, Swagger: `/docs`.
Префикс методов — **/api/v1/reactor**. Индексы моторов/STM32 — **0..2**.
Эти методы не заменяют существующие датчики и вентиляторы теплицы.
Авторизации/токенов нет. Все аппаратные обращения — одна FIFO с остальным API,
COM-порт держит только сервис. Не открывайте его параллельно в другой программе.
Rust-приложение не менялось.

## Методы

Во всех путях ниже подразумевается префикс `/api/v1/reactor`.

| Метод | Путь | JSON запроса / результат |
| --- | --- | --- |
| GET | /temperature | Общий DS18B20, °C, valid/fresh/age_ms |
| GET | /motors/{idx}/state | Уставки скоростей, режим, EN, микрошаг, тайминги |
| POST | /motors/{idx}/sps | `{"rate": -1234.125}` — STEP/с |
| POST | /motors/{idx}/rpm | `{"rate": 60}` — об/мин |
| POST | /motors/{idx}/stop | Без тела — остановить и выключить EN |
| POST | /motors/stop | Без тела — остановить все три одной командой Mega |
| POST | /motors/{idx}/enable | `{"enabled": true}` — удержание без движения |
| POST | /motors/{idx}/microstep | `{"divisor": 8}` — 4, 8, 16 либо 32 |
| GET | /stm/{idx}/voltage | Измеренное напряжение, мВ, может быть отрицательным |
| GET | /stm/{idx}/current | Измеренный ток, мА |
| GET | /stm/{idx}/voltage/setpoint | Исходная уставка напряжения, целые мВ |
| GET | /stm/{idx}/current/setpoint | Исходная уставка тока, мА |
| POST | /stm/{idx}/voltage/setpoint | `{"millivolts": 3001}`, целое 0..6000 |
| POST | /stm/{idx}/current/setpoint | `{"milliamps": 12.345}`, 0..50, до 3 знаков после точки |

POST скорости/stop/enable/microstep возвращают
`{"acknowledged": true, "received_at": "..."}`.
POST уставки STM32 возвращает подтверждённое исходное значение:
`{"idx": 0, "value": 12.345, "unit": "mA", "received_at": "..."}`.
Чтения U/I имеют тот же формат value/unit, но читают обратную связь, не уставки.
Один кадр SET STM32 не объединяет U и I в атомарную операцию.

### Скорость и состояние

`rate` — JSON-число со знаком, до трёх знаков после точки. Строки, bool,
NaN/Infinity, дополнительные поля и значения вне диапазона не принимаются.
SPS — импульсы STEP, то есть микрошаги. Для GD39ST34-0306B:
`SPS = RPM × 200 × делитель / 60`.
Максимум **7000 STEP/с**, это ограничение прошивки, не гарантированная скорость
механизма. При 1/4 максимум команды 525 RPM; при 1/8 — 262.5, при 1/16 — 131.25,
при 1/32 — 65.625. Превышение при текущем микрошаге Mega отклоняет без изменения
предыдущей уставки. Нулевая скорость — stop, ненулевая по модулю от 0.001 STEP/с.

Сохранены настройки разгона; STEP для idx 0/1/2 — D26/D29/D23:
переход 12 с, старт min(1000 STEP/с, целевая скорость по модулю).
Скорость можно менять на ходу. Реверс проходит через ноль.
Текущий диагностический вариант Mega генерирует STEP кооперативно из loop,
без собственных таймерных прерываний. Штатные Serial/Wire/Timer0 остаются.
Обслуживание моторов вызывается также в программных ожиданиях шлюза и STM32.
Блокировки библиотек OneWire/I2C могут задерживать STEP: фактическая частота
может быть ниже уставки, устойчивые 250 RPM на трёх моторах не гарантируются.
max_late_us — опоздание обслуживания loop, до 65535 мкс; resyncs — число
опозданий более 32 мкс. Для изменения генератора перепрошить только Mega.
ACK означает принятую уставку, **не завершение разгона и не факт вращения**.
При потере связи моторы продолжают выполнять последнюю команду. На старте
все остановлены. Опросы STM32/DS18B20 и обновления экранов не отключаются.
После обновления прошивки остаётся необходима стендовая проверка срыва двигателей.

GET state содержит:
- `idx`, `current_sps`, `target_sps`, `current_rpm`, `target_rpm`;
- `enabled`, `running`, `ramping`;
- `microstep` — делитель, `full_steps_per_rev` — 200;
- `max_late_us`, `resyncs` — диагностика задержек генератора;
- `measured: false`, `received_at`.

Это три последовательных аппаратных чтения, **не атомарный снимок**.
current_sps/current_rpm — текущая уставка генератора, не измеренная скорость.
Энкодеров нет. Диагностика не определяет пропущенные механические шаги.
Микрошаг меняется только при выключенном EN: stop → microstep → скорость.
Удержание включённого, но стоящего мотора тоже запрещает смену микрошага.

### Температура

Один общий DS18B20, отдельный VDD. Ответ: idx=0, value в °C,
valid, fresh, age_ms, received_at. Это кеш Mega; старше 3 секунд или
недоступный датчик — ошибка SENSOR_UNAVAILABLE, не число 0.
fresh означает возраст не более одного периода опроса (1 с); до 3 с данные
ещё valid, но могут быть fresh=false.
Это отдельный датчик от двух датчиков температуры теплицы на старом endpoint.

### Ошибки и безопасность

Неверный индекс/тип/диапазон — HTTP422; недоступный DS18B20/не готовая STM32 —
503; запрет изменения микрошага/EN движущегося мотора — BUSY/503.
Нет корректного ответа STM32/шлюза — DEVICE_TIMEOUT/504; ошибки содержат
device_status и данные аппаратной команды. Ошибки STM32 не подменяются уставками.
HTTP502 INTERNAL_ERROR возможна при некорректном подтверждении STM32.

Таймаут или ошибка ответа SET **не доказывают, что действие не произошло**:
проверяйте состояние/уставку перед дальнейшими действиями. Сервис не повторяет SET.
Stop проходит общей FIFO, может ждать предыдущий обмен. Это не аппаратная аварийная
кнопка и не гарантированное механическое торможение. OFF не добавлена.
SET_U/SET_I физически меняют аналоговые задания; проверяйте безопасную нагрузку.
Измеренная точность не следует из числа десятичных знаков.

## Ручная консоль

Из `tjc-commutator/chem-reactor-теплица`:

```powershell
py -3 scripts/api_console.py
```

Обычный безопасный обход чтений:

```text
reactor_temp
motor 0
stm 0 get_u
stm 0 get_i
stm 0 get_setted_u
stm 0 get_setted_i
selftest
```

Selftest берёт методы из OpenAPI: **35 GET API + OpenAPI**, только чтения.
Включённые моторы он не останавливает. Проверка связи не подтверждает механическую
и измерительную исправность.

Управление, только при безопасной нагрузке:

```text
motor_stop
motor_micro 0 1/4
motor_rpm 0 60
motor 0
motor_sps 0 -1000
motor_stop 0
motor_enable 0 1
motor_enable 0 0
stm 0 set_u 3001
stm 0 set_i 12.345
stm 0 get_setted_u
stm 0 get_setted_i
motor_stop
```

`rpm 0` / `set_pwm 0 100` остаются командами **вентиляторов теплицы**;
`motor_rpm` и `motor_sps` — шаговые двигатели Mega.
USB-консоль Mega использует индексы **1..3**, эта HTTP-консоль — **0..2**.
Новый адрес шлюза 17 не является вторым шлюзом вентиляторов ФабЛаб.

## Развёртывание и проверки

Одинаковая ветка `feat/chemical-reactor-integration` в трёх репозиториях.
Обновить хаб, добавить шлюз17, загрузить Mega и обновить сервис.
Полная инструкция сборки, подключения, wire-контракт и C++ bridge —
`tjc-sketch/chem-reactor-теплица/REACTOR.md`.

Сервис запускается как раньше:
`.venv\Scripts\python.exe -m hub_service --serial-port COM15`.
Указать свой порт МС-ТЮК. Библиотеки Python не изменились.
STM32 остаются на текущем протоколе v8; их прошивки и отдельный stm32-u-reader
этой интеграцией не меняются. Не подключать разные теплицы к одной шине.

Тесты без оборудования:
`.venv\Scripts\python.exe -m unittest discover -s tests -v`.
Для цепочки production C++ установить CHEM_REACTOR_CHAIN на bridge из инструкции;
CHEM_FIRMWARE_CHAIN опционально добавляет существующие узлы теплицы.
Тесты включают HTTP, FIFO, wire-кодек, console selftest, неверные аргументы,
read-only обход, PTY/pySerial на POSIX. Они не заменяют реальную прошивку и стенд.
