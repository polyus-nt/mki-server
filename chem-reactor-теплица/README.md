# Теплица-химреактор: сервис и прошивки

Самостоятельный проект: FastAPI, ручная HTTP-консоль, два скетча Arduino UNO,
прошивки хаба, двух Arduino-шлюзов, кнопочницы и восьмилампочницы.
Исходники runtime МС-ТЮК и библиотек датчиков включены локально;
внешний checkout lapki-compiler или соседних проектов для сборки не нужен.
Фаблаб-теплица в корне репозитория сохраняет свои прошивки и API.

Реализовано и проверено программно; физическое испытание нового стенда
проводит оператор после загрузки прошивок. Сервис не прошивает платы сам.

## Состав и адреса

| Узел | SimpleBus | Оборудование |
| --- | --- | --- |
| Центральный хаб | 12 | Маршрутизация запросов компьютера |
| Arduino-шлюз sensors | 13 | BMP280 ×2, DHT11 ×2, MQ-2 ×2 |
| Arduino-шлюз actuator | 14 | Два PWM-вентилятора, индексы 0/1 |
| Кнопочница | 15 | Концевики 0/1, Button(1)/Button(2) |
| lmp8 | 16 | Два замка на общем пине 1, шесть реле вентилятора на пинах 2–7 |

Компьютер — адрес 99. Это **отдельная физическая шина** химреактора.
Фаблаб использует пересекающиеся адреса: нельзя соединять оба комплекта
в одну шину без изменения адресации. Для параллельного запуска используйте
разные COM-порты и HTTP-порты: фаблаб по умолчанию 8000, химреактор 8001.
Автоматического определения типа стенда по подключённым платам нет:
оператор должен выбрать правильные прошивки и сервис.

Полная карта: [PINOUT.md](PINOUT.md). Два замка имеют общее управление
без индекса; пылесоса, SGP40/VOC и датчиков пыли здесь нет.
Матрица реле соответствует предоставленному скетчу; переключение выполняется
сначала в all-off, затем через 250 мс в новую комбинацию, без блокирующего delay.
Состояние выхода или подтверждение команды не доказывает физического срабатывания.

## 1. Собрать и загрузить прошивки МС-ТЮК

Все команды далее выполняются **из этой папки**, не из корня фаблаб-сервиса:

```powershell
cd "chem-reactor-теплица"
py -3 scripts/build.py --target all --toolchain-bin "C:\tools\arm-gnu\bin"
```

Нужен ARM GNU Toolchain с `arm-none-eabi-g++`, `arm-none-eabi-objcopy`,
`arm-none-eabi-size`. Если они доступны в PATH, `--toolchain-bin` не нужен.
Билдер проверяет закреплённые хеши локального runtime, нормализует CRLF
и применяет транспортные исправления только к сборочной копии.
Путь к toolchain выше — пример, укажите свой.

| Плата | Бинарник |
| --- | --- |
| Хаб 12 | `build/hub/sketch.bin` |
| Sensors-шлюз 13 | `build/gateways/sensors/sketch.bin` |
| Actuator-шлюз 14 | `build/gateways/actuator/sketch.bin` |
| Кнопочница 15 | `build/buttons/sketch.bin` |
| lmp8 16 | `build/lmp8/sketch.bin` |

Для отдельной платы: `--target hub`, `gateways`, `buttons` или `lmp8`.
Один шлюз: `py -3 scripts/build_gateways.py --gateway sensors` или `actuator`.
Для подготовки без компиляции добавьте `--prepare-only`.

Загружайте бинарники как **usercode по адресу `0x08003800`** штатным средством
прошивки соответствующей платы. Не в начало flash и не поверх загрузчика.
Загружать фаблаб-прошивку lmp8 сюда нельзя: её пины 2/3 имеют другое назначение.

## 2. Arduino IDE

Два самостоятельных проекта, выбрать плату **Arduino Uno**:

- [arduino-sensors/arduino-sensors.ino](arduino-sensors/arduino-sensors.ino)
  — датчики; SoftwareWire и DHT включены в `src`, дополнительные библиотеки
  для этого скетча не нужны.
- [arduino-actuator/arduino-actuator.ino](arduino-actuator/arduino-actuator.ino)
  — два вентилятора; установите **PinChangeInterrupt 1.2.9** через Library Manager.

В каждой папке есть собственный `BoardConfig.h`: вся распиновка настраивается там.
Не переключайте фаблаб-профили и не переименовывайте `.ino` отдельно от папки.
Перед каждым Upload выберите USB-порт нужной Arduino.
У actuator число импульсов тахометра на оборот задано `API_PULSES_PER_REV=2`;
проверьте его для своих вентиляторов.

Для sensors TEST раскомментируйте `#define TEST` в её `BoardConfig.h` и загрузите
скетч. В Serial Monitor выберите 9600 бод и окончание строки Newline:

```text
temp 0
pressure 1
humidity 0
gas 1
help
```

Вывод: status, человекочитаемое показание, fresh/age и HEX полного ответа v2.
TEST не выключает Austere: плата продолжает отвечать своему шлюзу.
Сериал-консоль Arduino и COM-порт МС-ТЮК — разные интерфейсы.
Начальные ответы BMP/DHT могут быть SENSOR_UNAVAILABLE до первого измерения.

## 3. Запустить FastAPI на Windows

Из папки `chem-reactor-теплица`, Python 3.10+:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m hub_service --serial-port COM15
```

Укажите свой COM-порт USB-интерфейса МС-ТЮК, **не** USB-порт Arduino.
Закройте все другие программы, владеющие этим портом. Один экземпляр сервиса,
один worker. Swagger: **http://127.0.0.1:8001/docs**.
Настройки: `--http-port`, `--host`, `--debug`, `--queue-capacity`,
`--queue-timeout`, `--exchange-timeout`. `MSTJUK_SERIAL_PORT` заменяет
`--serial-port`, если удобнее переменная окружения.

По умолчанию только localhost. При `--host 0.0.0.0` любой доступный сетевой
клиент может управлять аппаратурой: **токенов и авторизации нет**.
User/Admin — логические группы, не контроль доступа. Ограничьте доступ сетью.
На Linux: `python3 -m venv .venv`, затем `.venv/bin/python` вместо Windows-пути.

## 4. Ручная консоль и проверка

В другом терминале из той же папки:

```powershell
py -3 scripts/api_console.py
```

```text
health
probe
temp 0
pressure 1
humidity 0
gas 1
door 0
pwm 1
rpm 1
lock
relay
get_mode
selftest
```

`selftest` проходит все GET и все индексы: **20 запросов** плюс OpenAPI.
Не переключает выходы, продолжает после ошибок. Это проверка доступности,
не калибровки и не физической работы механизмов.

Следующие команды реально переключают оборудование; выполнять под наблюдением:

```text
set_pwm 1 100
set_relay_level 7
set_relay_level 0
set_door_lock 1
set_door_lock 0
set_mode 2 1
set_mode 0 1
```

Общий замок: **без индекса**, команда `set_door_lock 1` блокирует оба.
Разовый запуск: `py -3 scripts/api_console.py --command selftest`.
Адрес сервера можно изменить через `--url`, таймаут HTTP по умолчанию 45 с.
Полный список HTTP-методов, ответов и ошибок: [API.md](API.md).

## 5. Что проверено и что проверить на стенде

Программно: все ARM-бинарники, оба AVR-скетча (включая sensors TEST),
GPIO/распиновка, компенсация BMP280, кэши DHT/MQ-2, PWM/RPM, режимы,
все релейные комбинации, пауза 250 мс и wrap таймера; HTTP-валидация,
FIFO/таймауты/отмена и HTTP → pySerial → SimpleBus → production C++ API → HTTP.
В интеграционных проверках GPIO заменены тестовыми реализациями.

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v
py -3 scripts/test_firmware.py --cxx g++
```

Нативным тестам нужен C++11-компилятор. Для HTTP-тестов firmware chain укажите
его в `CXX`, если `g++` не в PATH. PTY-проверка выполняется только на POSIX.

На стенде отдельно проверить полярность силовых драйверов, отсутствие
нежелательных импульсов при reset/подаче питания, порядок мощности релейных
уровней, тахосигналы и монтаж концевиков. MQ-2 возвращает только ADC/напряжение;
прогрев и калибровка не определены, ppm не выдаются. Корректный ADC не доказывает
готовности газового датчика и не позволяет обнаружить отсоединение его выхода.
Программные команды не заменяют аппаратные защиты силовой схемы.
