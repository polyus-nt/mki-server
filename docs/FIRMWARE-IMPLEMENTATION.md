# Реализация прошивок, хаба и сервера

Эксперимент на отдельных ветках, не готовая система на стенде:

| Репозиторий | Ветка | Реализованный слой |
| --- | --- | --- |
| arduino-sensor | feat/hardware-api-firmware | Arduino endpoint, индексы нового состава, обработчики чтения и явные заглушки |
| arduino-actuator | feat/hardware-api-firmware | Arduino endpoint, шесть PWM/RPM, два сценария неисправности |
| tjc-sketch | feat/hardware-api-gateways | Два C++ Arduino-шлюза 13/14 и центральный хаб main-a4 |
| tjc-commutator | feat/hardware-api-firmware | Rust runtime/FIFO/User API, общий кодек и межрепозиторные тесты |

## Что работает в коде

Один фиксированный кадр 28 байтов, CRC-16/CCITT-FALSE, поля и порядок байтов
из [проекта протокола](HARDWARE-PROTOCOL.md). Повреждённый или частичный запрос
не применяется. Все Arduino проверяют аргументы до обращения к аппаратуре.
Парсер восстанавливается после повреждений и тайм-аутов, размер буферов ограничен.
Шлюзы принимают полный кадр, маршрутизируют его в Austere и возвращают ответ
хабу 12; проверяют корреляцию, тайм-аут, переполнение и поздние ответы.

На actuator нет PID, температурных решений, EEPROM-конфигурации и замков.
get_pwm возвращает применённое значение, set_pwm также возвращает его.
mode=1 меняет PWM сразу и раз в 30 секунд, даже без связи; set_pwm не сдвигает
таймер. mode=2 искажает только поступающие команды выбранному вентилятору.
Одновременно один сценарий; смена/выключение не восстанавливает прежний PWM.
RPM — u32 без прежней нормализации. GPIO-адаптер поддерживает шесть аппаратных
PWM и шесть таховходов с PinChangeInterrupt; считает RPM с настраиваемым числом
импульсов на оборот (пока 2). Частоту PWM отдельно предстоит согласовать.

На sensors get_temp/get_pressure имеют idx=0..2 (три BMP280), VOC/пыль/двери —
0..1, влажность — 0..2. Замки обслуживаются восьмилампочницей, поэтому обе
Arduino отклоняют set_door_lock как UNKNOWN_COMMAND.

Экспериментальные команды: 0x24 get_humidity реализован для DHT11×3,
0x25 get_dust возвращает ADC и напряжение GP2Y1010AU0F; без пинов — NOT_IMPLEMENTED.
Сервер публикует get_humidity и get_dust (ADC и напряжение без концентрации). Для трёх BMP280 реализован
драйвер с независимой калибровкой, общим SCL и отдельными SDA (SoftwareWire).
VOC представлен двумя SGP40 и официальным алгоритмом Sensirion: get_voc
возвращает VOC Index, не ppm и не сырой сигнал. DHT11 предоставляет влажность;
GP2Y1010AU0F считывается через LED-импульс/ADC, без расчёта концентрации. Концевики читаются после задания пинов и полярности;
до этого возвращают NOT_IMPLEMENTED, а не вымышленное состояние двери.

## Сборка и ограничения аппаратуры

В каждом Arduino-репозитории остался один актуальный корневой скетч:
`arduino-sensor/arduino-sensor.ino` и `arduino-actuator/arduino-actuator.ino`.
Их можно открыть непосредственно в Arduino IDE и собрать для Uno.
Старые скетчи, PID, EEPROM и legacy-заголовки удалены; восстановление — через Git.
Зависимости транспорта включены в `src/austere/`, SoftwareWire — в
`arduino-sensor/src/softwarewire/`. Arduino IDE рекурсивно компилирует `src/`.
`src/main.cpp` подключает корневой скетч только при сборке PlatformIO.
Настройки находятся в видимом IDE файле `BoardConfig.h`.

В обоих Arduino-репозиториях альтернативная сборка:

```sh
pio run -e uno
```

Это настоящие AVR ELF/HEX, но конфигурация намеренно не включает неизвестные
выходы/датчики. По умолчанию используются прежние транспортные пины из
исходников: MISO=2, MOSI=3, CLK=4, CS=5; IRQ=6 для sensors, IRQ=7 для actuator.
Это не утверждение новой разводки: все пять можно переопределить в board header.
Транспортные пины проверяются отдельно до любой настройки GPIO.

Для actuator нужен согласованный header с API_PWM_PINS и API_TACH_PINS —
двумя массивами по шесть пинов. HARDWARE_API_BOARD_HEADER указывает на него.
Не допускаются совпадения между PWM, tach и transport; PWM должны поддерживать
аппаратный analogWrite, таховходы — PinChangeInterrupt. Неверная карта не
включает вентиляторы и не возвращает ложное подтверждение применения PWM.
Текущая разводка transport использует D3/D5, два аппаратных PWM Uno: шесть
вентиляторов нельзя включить, просто дописав два пина к прежней карте.
Вся распиновка обеих Arduino централизована в их BoardConfig.h, включая
дефолты Austere; аппаратные драйверы не выбирают пины самостоятельно.
Карты для compile-check находятся в отдельных test/config-файлах и подключаются
через HARDWARE_API_BOARD_HEADER. Это не утверждённые карты стенда.
Распиновка/модель платы должны быть согласованы; платы и прошивки не прошиваются
автоматически.

```sh
pio run -e uno_compile_check
```

Дополнительная сборка actuator компилирует настоящую шестиканальную GPIO-ветку.
Её карта намеренно конфликтует с транспортом и должна отклоняться при setup.
Это проверка компиляции, НЕ карта для установки на стенд.

Sensor board header задаёт API_DOOR0_PIN/API_DOOR1_PIN и
API_DOOR0_CLOSED_LEVEL/API_DOOR1_CLOSED_LEVEL; при неверных/пересекающихся пинах
оба дверных канала остаются отключёнными.

BMP280 включаются только после задания всех четырёх констант
API_BMP_SCL_PIN/API_BMP_SDA0_PIN/API_BMP_SDA1_PIN/API_BMP_SDA2_PIN.
Четыре пина должны быть различными и не пересекаться с транспортом/дверями.
SCL=D2, SDA=D3/D4/D5 из пользовательского примера конфликтуют с транспортом:
эта карта НЕ включена по умолчанию. `pio run -e uno_bmp_compile_check`
проверяет компиляцию полной BMP-ветки, но не разрешает такую разводку.

Драйвер проверяет ID=0x58 и NVM, читает 24 байта калибровки, задаёт normal mode
с oversampling x1. Инициализация по шагам; одна I²C-операция на один poll.
Три датчика опрашиваются по кругу; T/P читаются вместе раз в 100 мс на датчик.
Локальная SoftwareWire 1.6.0 ограничивает всю операцию тайм-аутом 20 мс и
передаёт ошибку clock stretching адаптеру. I²C остаётся синхронным с ограниченным
ожиданием. При сбое сохраняется старая валидная пара с fresh=0 и растущим
возрастом; повторная инициализация через 1 с. До первого успешного измерения
SENSOR_UNAVAILABLE; без назначенных BMP-пинов — NOT_IMPLEMENTED.
Температура передаётся i32 в сотых °C, давление u32 в Па, big-endian;
data[4]=valid/fresh, data[5..6]=age_ms, data[7]=0. Например, 25.08 °C:
`00 00 09 CC 03 00 00 00`, 100653 Па: `00 01 89 2D 03 00 00 00`.
Это data внутри CRC-кадра, не отдельное сообщение или текстовые float.

## Два VOC SGP40

Драйвер SGP40 находится в отдельном `SGP40.h`, концевик — в `DoorSwitch.h`.
DHT11.h — отдельный драйвер влажности; GP2Y1010AU0F.h содержит драйвер кэша; src/GP2Y1010Hardware.h — импульс и ADC.
Общий BoardIO не содержит алгоритмов измерения.
Два независимых датчика, две SoftwareWire-шины и два статических состояния
официального [Gas Index Algorithm](https://github.com/Sensirion/arduino-gas-index-algorithm).
Алгоритм включён вместе с лицензией в `arduino-sensor/src/sensirion/`;
устанавливать внешнюю библиотеку для Arduino IDE не требуется.
У каждого SGP40 адрес 0x59, частота шины 50 кГц, тайм-аут операции 20 мс,
внутренние подтяжки отключены. Пины задаются явно в BoardConfig.h;
SDA=D7/SCL=D6 из примера не активированы, поскольку D6 занят IRQ транспорта.
Пересечения с Austere/BMP/концевиками запрещены. Без карты — NOT_IMPLEMENTED.

Раз в секунду отправляется команда `26 0F 80 00 A2 66 66 93` с фиксированной
компенсацией RH=50%, T=25 °C, как в пользовательском примере; это не реальные
показания DHT11/BMP280. Через 35 мс после завершения команды автомат читает
3 байта; `delay(35)` нет. Один poll BoardIO обслуживает один из десяти
BMP/VOC/DHT. В idle-итерации не выполняются несколько чтений подряд.
CRC-8: polynomial 0x31, init 0xFF. Ошибочные данные не поступают в алгоритм.
Каденс алгоритма совпадает с измерениями (1 с); пропущенные измерения не
восстанавливаются пачкой вызовов с одним старым raw. После перерыва/ошибки
алгоритм проходит повторную инициализацию: перерыв стартов >=2000 мс,
задержка чтения >=1000 мс, I²C/CRC-ошибка или raw вне диапазона core (1..64999).
Обычный небольшой джиттер допустим. Первичный blackout примерно 45 с:
нулевой выход алгоритма в этот период — не валидный VOC Index.

`get_voc(idx)` (0x21, node=13, idx=0..1) возвращает безразмерный индекс 1..500:
data[0..3]=u32 big-endian, data[4]=valid/fresh, data[5..6]=age_ms, data[7]=0.
Для свежего индекса 100 без возраста: `00 00 00 64 03 00 00 00`.
До первого валидного индекса — SENSOR_UNAVAILABLE; после ошибки ранее
измеренный индекс доступен как старый с fresh=0 и растущим age, насыщение 65534 мс.
Сырые SRAW и концентрация в ppm через этот метод не публикуются.

`pio run -e uno_sensors_compile_check` включает полный путь BMP/VOC/дверей
с отдельным тестовым config; Arduino CLI тоже проверен с ним.
Для BMP/VOC/дверей: Flash Uno 23068/32256 байт, статическая RAM 1358/2048.
Эта проверка не доказывает устойчивость обмена/стека на стенде.

## Три DHT11

Отдельный DHT11.h содержит период, валидацию и кэш каждого экземпляра;
src/DHT11Hardware.h использует локальную [Adafruit DHT 1.4.6](https://github.com/adafruit/DHT-sensor-library/tree/1.4.6).
MIT-лицензия сохранена; константа типа переименована DHT_TYPE_11 во избежание
конфликта с классом DHT11. Захват импульсов прерывается на первом timeout.
API_DHT0_PIN/API_DHT1_PIN/API_DHT2_PIN задаются вместе в BoardConfig.h,
по умолчанию выключены. Пины 8/9/10 из примера не включаются автоматически:
в тестовой карте они заняты VOC. Проверяется пересечение со всеми другими группами.

Начальное ожидание 2 с, затем минимум 2 с после завершения каждой попытки;
нагнать пропуски пачкой чтений нельзя. В API GPIO не читается, возвращается кэш.
Checksum/NaN/диапазон проверяются до публикации; ошибка сохраняет последний
валидный результат с fresh=0. Без карты — NOT_IMPLEMENTED; до первого
успешного измерения — SENSOR_UNAVAILABLE.
get_humidity (0x24, node=13, idx=0..2): data[0..3] u32 в сотых % RH (0..10000),
data[4] flags, data[5..6] age_ms (максимум 65534), data[7]=0. Например, 55.5%:
`00 00 15 AE 03 00 00 00` для свежего измерения с нулевым возрастом.
Это масштаб протокола, не фактическая точность DHT11.

Физическое чтение синхронное: 1+20 мс стартовые задержки, затем временное
отключение прерываний для импульсов. Оно начинается в idle после Austere;
Arduino сама тактирует обмен, но влияние задержек и стека требует стендовых тестов.
`pio run -e uno_dht_compile_check` использует искусственную карту
test/compile_only_dht.h. Полная сборка: Flash 24608/32256, RAM 1441/2048,
остаток 607 байт для стека; в DHT есть локальный массив захвата 320 байт.
Без согласования разводки эту конфигурацию нельзя прошивать.

AustereSerialMaster включён в каждый Arduino-репозиторий из ArduinoUno library
[lapki-compiler, pinned source](https://github.com/kruzhok-team/lapki-compiler/tree/c0e235f364f21b1a7ba8dbb598ef0bc983511af6/compiler/library/ArduinoUno/1.0/source).
Лицензия upstream GPLv3 сохранена рядом с исходниками; исходная библиотека не
переписана. Её один байтовый transfer синхронный (~4.7 мс): основной цикл не
блокируется ожиданием всей команды, но прошивка не объявляется полностью
неблокирующей на уровне битового транспорта.

ARM-сборки и поправки аппаратных библиотек шлюза описаны в
[GATEWAY-FIRMWARE.md](../../tjc-sketch/docs/GATEWAY-FIRMWARE.md).

## Проверки

Из tjc-commutator, с GCC и Python 3:

```sh
python3 scripts/test_firmware.py
python3 scripts/test_firmware.py --sanitize
```

Проверяются одинаковость четырёх копий общего header, CRC, повреждения/обрывы,
восстановление парсера, переполнение millis, ответы/ошибки, все шесть вентиляторов,
режимы и удержание PWM. 44 актуальных golden request/response проверяют кодирование и API-результаты;
старый маршрут замков заменён отрицательными UNKNOWN_COMMAND примерами,
добавлены третий BMP280, VOC Index и DHT11. Физические измерения не эмулируются
как доказательство подключения датчиков.
BMP-тесты проверяют компенсацию, изоляцию калибровок, отрицательную температуру,
плохой ID, повторы, fresh/age, единицы и переполнение millis.
SGP40-тесты проверяют CRC, независимость двух алгоритмов, blackout, каденс,
джиттер/пропуски, тайм-аут чтения, ожидание после окончания I²C, stale/fresh,
переполнение времени, диапазон и wire-layout VOC Index.
BoardIO-mock тест использует настоящие драйверы и проверяет две двери,
один опрос за poll, три DHT-кэша и полные/конфликтующие/отключённые карты.
Отдельно проверены периоды/ошибки/качество DHT11 и настоящий Adafruit-код
с mock импульсами: декодирование, checksum, force=true и первый timeout.
Отдельный GPIO-mock тест самой SoftwareWire проверяет общий deadline при
зависшем SCL, пустой RX вместо выдуманных данных, сброс ошибки следующей
транзакцией, освобождение SDA/SCL и переполнение времени.
Санитайзеры ASan/UBSan проверяют host-код, не GPIO на AVR/STM32.
Отдельный интеграционный тест пропускает запросы через оба автомата шлюза и
обработчики Arduino с mock-аппаратурой: проверяет неизменность кадров, ошибки,
применённый PWM, потерю ответа после реального изменения mock-выхода и отсутствие
автоматического повтора. Это не замена стендовому обмену.

## Центральный хаб и сервер

Центральный main-a4 хаб реализован в tjc-sketch/firmware/hub:
одна USART1/SimpleBus-линия для компьютера и шлюзов, запросы адресу 12,
пересылка на 13/14, ответы компьютеру 99. Один активный запрос, корреляция,
тайм-аут 3 с, recovery quiet 250 мс с пределом 1000 мс.
Нативные тесты проходят через Hub → Gateway → Arduino в обе стороны;
ARM-сборка выполнена, без прошивки стенда.

Rust production runtime теперь использует эти же 28-байтовые кадры:
один serial-owner worker, ограниченная общая FIFO, реальные отложенные ответы
GUI/MCP, актуальные датчики и шесть вентиляторов. Старые PID/config/emergency
команды удалены. SQLite-история сохраняется; GUI отображает температуры/RPM,
качество/возраст данных и локальный Admin API. MCP имеет только UserApi,
без ссылок на административный broker; набор tools не включает режимы.
По умолчанию MCP read-only, PWM разрешён только TJC_AGENT_PHASE=full.

Проверки Rust: CRC/44 общих golden-вектора с API-результатами, повреждения,
частичные кадры/шум, корреляция, FIFO, реальные async-результаты, дубликаты и
конфликты decision_id, capacity, тайм-аут/отключение, защиту от старой сессии при повторе tx_id, 70000 запросов без остановки
и восстановление журнала решений из SQLite, bearer auth, граница User/Admin и настоящий serial owner через Linux PTY.
PTY — не проверка электрической линии. History-тест разделяет idx и исключает
повторное усреднение кэша при RPM/других ответах.

Очередь 64 + один активный, ожидание очереди 30 с, обмен 5 с.
decision_id записывается в SQLite до приёма команды и сохраняет её результат.
В памяти остаётся ограниченный кэш 4096 результатов; вытеснённые доступны из БД.
tx_id 1..65535 переиспользуется только после увеличения session_id: опрос и
очередь не останавливаются. Незавершённое решение после рестарта не повторяется;
его неизвестный исход требует проверки аппаратуры.
Подробные правила и восстановление описаны в HARDWARE-PROTOCOL.md.

Восьмилампочница ещё не реализована; её адрес/команды замков и пылесоса
не назначены. Проект остаётся экспериментальным до согласования разводки и
сквозной проверки на стенде. Старые GraphML несовместимы с новым кадром.
