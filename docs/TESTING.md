# Проверка ФабЛаб-теплицы и теплицы-химреактора

Проверяем по слоям: Arduino и датчики → Arduino и вентиляторы →
USB/хаб → отдельные аппаратные ветви → полный FastAPI API.
Прошивки двух теплиц различаются: не смешивайте их на одной шине.
Это гайд для Windows; COM-порты в примерах замените своими.

## 1. Подготовка и безопасность

- Скачайте актуальные ветки: `feat/hardware-api-firmware` в arduino-sensor
  и arduino-actuator, `feat/hardware-api-gateways` в tjc-sketch,
  `feat/fastapi-hub-service` в tjc-commutator.
- Полная распиновка ФабЛаб:
  [tjc-sketch/docs/PINOUT.md](../../tjc-sketch/docs/PINOUT.md).
  Химреактор:
  [tjc-sketch/chem-reactor-теплица/PINOUT.md](../../tjc-sketch/chem-reactor-теплица/PINOUT.md).
  Вкладка BoardConfig.h в Arduino IDE — источник пинов прошиваемой Arduino.
- Выберите Arduino Uno и нужную плату. Для актуаторов установите
  PinChangeInterrupt 1.2.9 через менеджер библиотек; библиотеки датчиков
  включены в репозиторий.
- Общий GND обязателен. Питание моторов/замков подавайте через предусмотренные
  силовые драйверы/реле, не с GPIO. Проверьте уровни между Arduino и МС-ТЮК,
  питание и подтяжки датчиков по схеме своего стенда.
- Перед изменением проводки отключите питание. Вращающиеся части оградите.
  Оставьте доступ к аварийному отключению питания и выходу из помещения.
  LOW/HIGH на GPIO сами по себе не доказывают правильное подключение нагрузки.
- Одним COM-портом владеет одна программа: Arduino Serial Monitor,
  sensor_console, hub_test_console или FastAPI. Не запускайте их одновременно
  на одном порте.
- При потере связи последнее PWM удерживается. Остановка консоли/сервиса
  **не выключает вентиляторы, пылесос или замки**. Тесты завершайте явными
  командами выключения и проверкой результата; при потере обмена используйте
  физическое отключение питания, а не повторяйте команды вслепую.

## 2. Датчики отдельно, без МС-ТЮК

Подключите только сенсорную Arduino, датчики и её USB. Хаб и шлюз не нужны.
Откройте соответствующий скетч:

| Теплица | Репозиторий | Открыть в Arduino IDE |
| --- | --- | --- |
| ФабЛаб | arduino-sensor | arduino-sensor.ino в корне |
| Химреактор | arduino-sensor | chem-reactor-теплица/arduino-sensors/arduino-sensors.ino |

В BoardConfig.h раскомментируйте `#define TEST`, загрузите прошивку.
Откройте Serial Monitor: **9600 бод**, окончание строки Newline или Both NL & CR.
По одному отправляйте команды; после загрузки дайте датчикам время на первые
измерения. Это реальные чтения того же SensorApi, не симуляция.

ФабЛаб:

```text
help
temp 0
temp 1
temp 2
pressure 0
pressure 1
pressure 2
voc 0
voc 1
humidity 0
humidity 1
humidity 2
dust
```

Пыль — один GP2Y1010AU0F: ADC **A1**, LED **A2**. Команда `dust` не принимает
индекс; `dust 0` — ошибка. Возвращаются ADC и напряжение, не концентрация.
Для VOC допускается SENSOR_UNAVAILABLE в начале прогрева алгоритма
(около 45 секунд); после него ожидается VOC Index 1..500.
DHT11 обновляет влажность не чаще раза в две секунды.

Химреактор:

```text
help
temp 0
temp 1
pressure 0
pressure 1
humidity 0
humidity 1
gas 0
gas 1
```

MQ-2 возвращает ADC/напряжение, не ppm. Корректный ADC не доказывает
наличие датчика или завершение его прогрева. Не используйте опасные газы
для проверки: сначала проверьте проводку, напряжение и штатное поведение.

Ожидается status=0, правдоподобные единицы и значения, обновляющийся age_ms.
`fresh=false` нормально при повторном чтении кэша; ориентируйтесь также
на возраст. При ошибке не считайте выведенный ноль измерением.
TX HEX показывает бинарный ответ, сформированный тем же API.
TEST не отключает Austere: Arduino продолжает отвечать шлюзу.
USB-проверка **не проверяет** проводку Austere, шлюз и хаб.

После диагностики закомментируйте TEST и перепрошейте обычную сборку,
либо осознанно оставьте TEST на время стендовой проверки.

## 3. Вентиляторы Arduino отдельно, без МС-ТЮК

Нужны только конкретная actuator Arduino, её вентиляторы/реле/тахометры,
силовое питание и USB. Откройте свой самостоятельный проект:

| Теплица / плата | Путь в arduino-actuator | Локальные индексы USB TEST | Индексы FastAPI |
| --- | --- | --- | --- |
| ФабЛаб, первая | arduino-actuator-1/arduino-actuator-1.ino | 0..3 | 0..3 |
| ФабЛаб, вторая | arduino-actuator-2/arduino-actuator-2.ino | 0..1 | 4..5 |
| Химреактор | chem-reactor-теплица/arduino-actuator/arduino-actuator.ino | 0..1 | 0..1 |

В её BoardConfig.h включите TEST, загрузите скетч; Serial Monitor:
9600 бод, Newline. Команды:

```text
help
pwm 0
rpm 0
set_pwm 0 100
pwm 0
rpm 0
set_pwm 0 0
pwm 0
rpm 0
```

Это **физическое управление**. 100 — пример PWM 0..255, не процент
и не гарантия запуска вашего вентилятора. Выбирайте значение под оборудование.
После SET подождите не менее секунды и повторите RPM; после выключения
дайте вентилятору остановиться. Повторите для каждого локального индекса.

Ожидается:
- после загрузки PWM=0, питание выключено: первая Arduino ФабЛаб — реле HIGH,
  вторая Arduino ФабЛаб и Arduino химреактора — LOW;
- при PWM>0 питание включено: первая Arduino ФабЛаб — LOW,
  вторая Arduino ФабЛаб и Arduino химреактора — HIGH; get_pwm совпадает с применённым значением;
- вращение видно физически и в RPM; при неподвижном вентиляторе RPM=0;
- после `set_pwm idx 0` питание выключено, PWM=0;
- `set_pwm 0 256` и индекс вне диапазона отклоняются, выходы не меняются.

RPM по умолчанию рассчитывается для двух импульсов на оборот —
сверьте с вентилятором. Проверка цифры PWM не заменяет проверку выходного
сигнала осциллографом и подключения реле.
USB TEST не предоставляет команды отказа; в химреакторе их нет вообще.
У второй ФабЛаб Arduino USB idx=0 соответствует FastAPI idx=4.

После проверки каждого канала выключите его явной командой, затем верните
обычную сборку без TEST. Эта проверка не требует Arduino-шлюза.

## 4. МС-ТЮК: сборка и проверка USB/хаба

Сборка из корня tjc-sketch для ФабЛаб:

```powershell
py -3 scripts/build.py --target all --toolchain-bin "C:\ARM-GCC\bin"
```

Для химреактора сначала перейдите в его папку:

```powershell
cd chem-reactor-теплица
py -3 scripts/build.py --target all --toolchain-bin "C:\ARM-GCC\bin"
```

Замените каталог ARM GCC своим; при компиляторе в PATH параметр можно убрать.
Билд создаёт файлы в build/, но **не прошивает платы**.
Порядок загрузки пользовательского кода и адреса описаны в README
соответствующего проекта tjc-sketch. Не загружайте usercode бинарник
как полный образ с загрузчиком по неверному адресу.

Для проверки только USB/центральной платы используйте отдельный hub-test:
собирается из **корня** tjc-sketch, не папки химреактора.

```powershell
py -3 scripts/build.py --target hub-test --toolchain-bin "C:\ARM-GCC\bin"
py -3 -m pip install pyserial
py -3 scripts/hub_test_console.py COM15
```

Сначала загрузите `build/hub-test/sketch.bin` штатным способом на центральную
плату. В консоли введите `3`: ожидается ответ 0xAA.
Для этой проверки нижние платы не нужны. Если RX=0, проверяйте именно
USB-порт, кабель, питание и центральную плату; не датчики.
После проверки **обязательно верните обычную прошивку хаба своей теплицы**.
hub-test не является API-хабом и не сможет маршрутизировать запросы датчикам.

## 5. Проверка отдельной аппаратной ветви

Соберите минимум: PC → обычный хаб → один нужный шлюз → проверенная Arduino.
Остальные ветви можно временно не подключать.
Для buttons/lmp/lmp8 Arduino-шлюз не нужен: PC → хаб → сама плата.

| Узел | ФабЛаб | Химреактор |
| --- | --- | --- |
| Хаб | 12 | 12 |
| Sensors-шлюз | 13 | 13 |
| Actuator-шлюз | 14: вентиляторы 0..3; 17: вентиляторы 4..5 | 14: вентиляторы 0..1 |
| Кнопочница | 15 | 15 |
| lmp ФабЛаб / lmp8 химреактора | 16 | 16 |

Запустите FastAPI своей теплицы (раздел 6), затем HTTP-консоль.
Вызывайте только методы проверяемой ветви: при неполном стенде полный
selftest закономерно выдаст ошибки отсутствующих узлов.
`get_mode` ФабЛаб требует обеих actuator-ветвей: для проверки одной ветви
используйте только PWM/RPM.

Проверка sensors: temp/pressure/humidity и VOC+dust для ФабЛаб
или gas для химреактора. Значения должны совпадать по смыслу с USB TEST.
DEVICE_TIMEOUT при успешной USB-проверке сужает поиск до шлюза,
Austere-проводки, питания и транспорта МС-ТЮК; это не доказательство
конкретного неисправного провода.

Кнопочница: `door 0`, `door 1`; замкните соответствующий вход на GND
по утверждённой схеме. После debounce (~50 мс) ожидается closed=true,
при размыкании false. Каждый концевик проверяется отдельно.

Обычная lmp ФабЛаб: `lock 0`, `lock 1`, `vacuum`; ручные команды
`set_door_lock 0 1` / `set_door_lock 0 0`,
аналогично idx1; `set_vacuum 1` / `set_vacuum 0`.
Замки: LOW блокирует, HIGH разблокирует; пылесос HIGH включает, LOW выключает.
Проверяйте физическую нагрузку, не только возвращаемое состояние выхода.

lmp8 химреактора: `lock`, `set_door_lock 1` / `set_door_lock 0` —
оба замка на одном пине 1. `relay`, `set_relay_level 0..10` —
релейный вентилятор на пинах 2..7: LOW включает, HIGH выключает.
Общий замок: LOW блокирует, HIGH разблокирует.
Переключение разрывает все реле (HIGH)
на 250 мс перед новой комбинацией. Все уровни проверяйте под наблюдением,
по утверждённой электрической схеме; завершите `set_relay_level 0`.
Последовательность допустимых комбинаций есть в PINOUT химреактора.

В buttons/lmp/lmp8 нет такой же USB TEST-консоли, как у Arduino.
Описанная проверка изолирует ветвь, **но включает рабочий хаб**;
чисто программные проверки без железа перечислены в разделе 7.

## 6. Полный стенд через FastAPI

Подключите все платы своей теплицы, прошейте соответствующие проекты.
В tjc-commutator подготовьте Python-окружение по README.
ФабЛаб, из корня:

```powershell
.venv\Scripts\python.exe -m hub_service --serial-port COM15
```

Во втором терминале, тоже из корня:

```powershell
py -3 scripts/api_console.py --url http://127.0.0.1:8000
```

Химреактор, из chem-reactor-теплица (если .venv создано в корне):

```powershell
..\.venv\Scripts\python.exe -m hub_service --serial-port COM15
```

Во втором терминале из той же папки:

```powershell
py -3 scripts/api_console.py --url http://127.0.0.1:8001
```

Для двух одновременно работающих стендов укажите **разные COM-порты**.
Swagger: http://127.0.0.1:8000/docs или http://127.0.0.1:8001/docs.

В HTTP-консоли:

```text
health
probe
selftest
```

health проверяет процесс/порт, не датчики. probe проверяет ответ хаба,
не нижние узлы. selftest последовательно вызывает все GET для всех
предусмотренных каналов и продолжает после ошибок.
Он **не отправляет управляющие POST**, не включает оборудование и не доказывает
работу двигателей/замков. Проверка fresh может влиять на общий флаг новизны.

Затем вручную повторите тест PWM/RPM из раздела 3 через команды
`set_pwm idx value`, `pwm idx`, `rpm idx` с глобальными индексами FastAPI.
Проверьте концевики, замки и прочие выходы по разделу 5.
Не запускайте selftest-writes: такой команды нет.
Если тестировали отказ в ФабЛаб, завершите `set_mode 0 0`, затем
выключите каждый вентилятор. В химреакторе get_mode/set_mode должны
отклоняться, а HTTP /api/v1/admin/mode — возвращать 404.

Графики — дополнительные HTTP-клиенты, не владельцы COM:
ФабЛаб `sensor-plots/`, химреактор `chem-reactor-теплица/sensor-plots/`.
Запуск `cargo run --release` из нужной папки; параметры и зависимости
смотрите в README выбранной программы.
При одновременном опросе графиками selftest может выполняться дольше:
все аппаратные запросы проходят через единственную FIFO.

В окнах Rust также есть панель «Команды на платы». Для проверки PWM:
`set_pwm 0 100`, затем `get_pwm 0`, `get_rpm 0`; в конце `set_pwm 0 0`.
Для ФабЛаб: `set_door_lock 0 0`, `lock 0`, затем `set_door_lock 0 1`;
`set_vacuum 1`, `vacuum`, затем `set_vacuum 0`.
Для химреактора: `set_door_lock 0`, `lock`, затем `set_door_lock 1`;
`set_relay_level 1`, `relay`, затем `set_relay_level 0`.
Проверяйте не только успешный HTTP-ответ, но и физическое состояние.
Не выполняйте переключения без безопасных условий на оборудовании.
При таймауте команда могла исполниться: сначала прочитайте состояние,
не повторяйте запись вслепую. Ручные записи автоматически не повторяются.

## 7. Автоматические проверки без железа

Нужны Python и нативный C++ компилятор g++ (это не ARM GCC).
Все команды выполнять из указанной папки:

| Папка | Команда | Что проверяется |
| --- | --- | --- |
| arduino-actuator | py -3 scripts/test_projects.py --cxx g++ | API/GPIO/PWM/RPM обеих ФабЛаб UNO, TEST-парсер |
| arduino-actuator/chem-reactor-теплица | py -3 scripts/test_firmware.py --cxx g++ | Два вентилятора, отсутствие режимов отказа, TEST-парсер |
| arduino-sensor/chem-reactor-теплица | py -3 scripts/test_firmware.py --cxx g++ | SensorApi, BMP280, DHT11 |
| tjc-sketch/chem-reactor-теплица | py -3 scripts/test_firmware.py --cxx g++ | Настоящие C++ API/state machines всей цепи, fake GPIO |
| tjc-commutator | .venv\\Scripts\\python.exe -m unittest discover -s tests | ФабЛаб FastAPI, FIFO, кодек, serial и консоль |
| tjc-commutator/chem-reactor-теплица | ..\\.venv\\Scripts\\python.exe -m unittest discover -s tests | FastAPI химреактора, FIFO, кодек, serial и консоль |
| Каждая папка sensor-plots | cargo test | Разбор измерений и история графиков |

Сквозной C++ тест химреактора требует соседние arduino-sensor и arduino-actuator.
Он не требует подключённых плат. Для HTTP → serial → C++ цепочки
экспортируйте bridge и подключите его к тестам сервиса:

```powershell
# В tjc-sketch/chem-reactor-теплица:
py -3 scripts/test_firmware.py --cxx g++ --bridge-out build/tests/firmware-chain.exe
# В tjc-commutator/chem-reactor-теплица:
$env:CHEM_FIRMWARE_CHAIN = "C:\projects\tjc-sketch\chem-reactor-теплица\build\tests\firmware-chain.exe"
..\.venv\Scripts\python.exe -m unittest discover -s tests
Remove-Item Env:CHEM_FIRMWARE_CHAIN
```

Настоящий pyserial/PTY участок теста выполняется на Linux/macOS; на Windows
он явно пропускается. Остальные проверки запускаются и на Windows.
Автотесты подтверждают код/формат, **не физическую проводку или исправность датчика**.

## 8. Как локализовать проблему

| Симптом | Сначала проверить |
| --- | --- |
| Arduino TEST не даёт корректного измерения | Питание/пины/библиотеку датчика; SENSOR_UNAVAILABLE до первого измерения |
| hub-test RX=0 | Выбранный USB-порт, кабель, питание, центральную плату |
| probe успешен, чтение даёт DEVICE_TIMEOUT | Нужную нижнюю ветвь, адрес шлюза, его прошивку, Austere-проводку |
| PWM читается правильно, RPM=0 | Вращение, питание/реле, тахометр, pulses/rev; допустимость стартового PWM |
| health ready, selftest с ошибками | health не опрашивает железо; смотреть код ошибки конкретного GET |
| HTTP 404 у dust/0 или admin/mode химреактора | Это удалённые методы: dust без индекса, отказов у химреактора нет |
| age_ms растёт до 65534 | Сохранённый кэш может быть старым: проверить обновления, а не только valid |

## Кнопочное открытие дверей — обе теплицы

Обновите хаб, кнопочницу и исполнительную плату (lmp ФабЛаб / lmp8 химреактора)
из соответствующей папки tjc-sketch,
а также сервис/sensor_console: они теперь ждут свободную шину перед запросом.
Arduino ради кнопок обновлять не нужно. Сначала проверяйте без силовой нагрузки
и обеспечьте ручное разблокирование/выход.

1. При запуске оба замка заблокированы: ФабЛаб lmp 1/2 LOW;
   химреактор общий выход 1 LOW. Пылесос ФабЛаб выключен, реле химреактора выключены.
   Концевики показывают реальный контакт, независимо от блокировки.
2. После установления связи нажмите кнопку 3: ФабЛаб открывается замок idx=0;
   в химреакторе открываются оба. Через 2 секунды после применения команды
   выход возвращается в блокировку. Кнопка 4 в ФабЛаб открывает idx=1,
   в химреакторе снова оба.
3. Держите кнопку более 2 секунд: продления нет. Отпустите и нажмите снова
   до окончания предыдущего импульса: таймер отсчитывает новые 2 секунды.
4. Закройте FastAPI/консоль, отключите компьютер: кнопки продолжают работать,
   пока хаб, кнопочница, исполнительная плата и шина питаются.
   Отключите шину исполнительной платы
   после фактического открытия: блокировка всё равно возвращается по таймеру.
5. Во время открытия задайте через API lock_state=true: блокировка немедленная.
   Повторите с false: таймер отменён, выход остаётся разблокированным.
   Затем явно восстановите true.
6. Зажатая при старте кнопка не должна открыть замок: отпустите и нажмите заново.
   После перезапуска хаба дождитесь первого опроса; старые нажатия не проигрываются.

Концевики химреактора: API idx=0/1, физические пины кнопочницы 1/2.
Кнопки открытия — отдельные пины 3/4. При общем выходе замков концевики
по-прежнему читаются независимо. Задержка шины/очереди предшествует
двухсекундному отсчёту; он начинается на исполнительной плате, а не в момент нажатия.

Полная логика и внутренние команды описаны в tjc-sketch/docs/DOOR-CONTROL.md.

## Исполнительные платы и полярность выходов

ФабЛаб использует обычную трёхвыходную lmp-a3, а не lmp8.
Из корня tjc-sketch: py -3 scripts/build.py --target lmp,
результат build/lmp/sketch.bin. Старый корневой образ build/lmp8 не использовать.
Для химреактора: из его папки py -3 scripts/build.py --target lmp8,
результат build/lmp8/sketch.bin. Химреактор остаётся на восьмилампочнице.

Перед силовым подключением измерьте уровни:
ФабЛаб 1/2 LOW (замки закрыты), 3 LOW (пылесос выключен);
химреактор 1 LOW (оба замка закрыты), 2..7 HIGH (реле выключены).
При кнопочном открытии замок становится HIGH и через 2 с возвращается LOW.
Для всех 11 уровней химреактора: сначала все шесть реле HIGH минимум 250 мс,
затем только выбранные выходы LOW. Завершите уровнем 0.
Реле первой Arduino ФабЛаб LOW-активные: LOW включает, HIGH выключает.
Вторая Arduino ФабЛаб и Arduino химреактора HIGH-активные: HIGH включает, LOW выключает.
После коррекции полярности перепрошейте соответствующие Arduino-актуаторы.
Хаб, кнопочницу и Arduino ради этой коррекции обновлять не нужно.
