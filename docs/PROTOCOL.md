# Транспорт сервиса: Hardware API v2

9600, 8N1, без flow control. Компьютер 99 (`63`), хаб 12 (`0C`),
sensors-шлюз 13, actuator-1 шлюз 14, кнопочница 15, обычная lmp 16, actuator-2 шлюз 17.
Хаб/шлюзы — SimpleBus, шлюз/Arduino — AustereMaster. Сервис не общается с Arduino USB.

Один полезный байт: `CR | два ASCII HEX адреса | byte | LF`.
Например, отправка байта 3 хабу: `0D 30 43 03 0A`.
API-кадр состоит из 28 таких пакетов; после каждого — минимум 2 мс паузы.
На Windows `flush()` не используется: его опрос очереди с шагом 50 мс может
растянуть 28 пакетов за пределы бюджета сборки кадра. Вместо этого есть ограниченный
контроль TX-очереди, минимальное время передачи 8N1 и межпакетная пауза.
RTS/DTR не используются для ручного управления направлением.

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 2 | magic A5 5A |
| 2 | 1 | version=2 |
| 3 | 1 | kind=1 запрос, 2 ответ |
| 4 | 2 | tx_id, Big Endian |
| 6 | 1 | node |
| 7 | 1 | command |
| 8 | 1 | status |
| 9 | 1 | idx |
| 10 | 8 | data |
| 18 | 8 | session_id, Big Endian |
| 26 | 2 | CRC-16/CCITT-FALSE, Big Endian |

CRC охватывает байты 2..25: poly1021, initFFFF, без отражения и xorout.
Для `123456789` результат 29B1. В GET-запросе status и data нулевые.
Ответ принимается только при совпадении version/kind/session/tx/node/command/idx.
Ошибочный CRC, старый ответ или неверный payload не завершают ожидание.
Парсер ограничен окнами 5/28 байтов; partial API сбрасывается через 250 мс
между байтами или 1000 мс общей длительности.

Сессия создаётся случайной ненулевой u64. tx_id=1..65535, затем сессия
увеличивается и tx_id снова 1; нулевую сессию пропускаем. Лимита на общее
число запросов нет. Сессия не является авторизацией.

| GET | Код hex | Узел | Индексы |
| --- | --- | --- | --- |
| температура | 20 | 13 | 0..2 |
| VOC | 21 | 13 | 0..1 |
| двери | 22 | 15 | 0..1 |
| давление | 23 | 13 | 0..2 |
| влажность | 24 | 13 | 0..2 |
| пыль | 25 | 13 | 0..1 |
| PWM | 30 | 14 | 0..5 |
| RPM | 31 | 14 | 0..5 |
| состояние замка | 43 | 16 | 0..1 |
| пылесос | 52 | 16 | внутренний fixed0, публичного индекса нет |
| режим неисправности (Admin) | 40 | виртуальный14 | FF |

Для компьютера node14 обозначает единый actuator API, индексы 0..5.
Физический маршрут для idx0..3: node14, локальный индекс без изменения.
Для idx4..5 хаб отправляет кадр node17, idx0..1. На обратном пути хаб
восстанавливает исходные node14, глобальный idx, session_id и tx_id,
пересчитывая CRC. HTTP-адреса и сопоставление ответов сервиса не меняются.
Прямое обращение компьютера к node17 запрещено хабом.

| SET | Код hex | Узел / idx компьютера | data запроса | Ответ OK |
| --- | --- | --- | --- | --- |
| PWM (User) | 32 | 14 / 0..5 | u8 PWM0..255 +7zeros | применённый u8 PWM +7zeros |
| режим (Admin) | 41 | 14 / 0..5 | u8 mode0..2 +7zeros | mode, global idx, +6zeros |
| замок (Admin) | 42 | 16 / 0..1 | bool lock_state +7zeros | 8zeros |
| пылесос (Admin) | 53 | 16 / fixed0 | bool mode (0=off,1=on) +7zeros | 8zeros |

GET_MODE: запрос idx=FF,data=0; ответ mode0..2 и глобальный индекс выбранного
вентилятора. В режиме0 индексFF (в HTTP `null`). SET_MODE всегда содержит
допустимый индекс0..5; при mode0 его значение игнорируется. Режим1 периодически
меняет PWM через30с и продолжает без компьютера; режим2 меняет только новые
SET_PWM выбранного вентилятора. Сброс режима не восстанавливает прежний PWM.
Хаб читает обе платы, затем подтверждает сброс обеих, затем включает одну;
ошибка останавливает цепочку. Повтор текущего режима/индекса идемпотентен.
Для режимов бюджет хаба4с (прочие3с), с обычным HTTP exchange_timeout5с.
Arduino/шлюзы и HTTP-сервис не аутентифицируют запросы. User/Admin обозначают
логические группы методов, а не проверку прав.

Температура: i32 сотых °C; давление: u32 Па; влажность: u32 сотых %RH;
VOC: u32 Index1..500. Затем flags=1/3, u16 age_ms0..65534, reserved0.
Пыль: u16 ADC0..1023 + u16 мВ, затем те же quality/age.
PWM: u8+7zeros; RPM: u32+4zeros. Дверь/замок/пылесос: bool0/1+7zeros.
Все числа Big Endian. При ошибке data целиком нулевые.
В физическом кадре присутствуют индексы и идентификаторы; HTTP-клиент не
конструирует их самостоятельно.

User HTTP предоставляет чтения и SET_PWM. Остальные SET и GET_MODE находятся
под `/api/v1/admin`; они доступны напрямую без токенов или Authorization.
Релейный вентилятор 0x50/0x51 оставлен в прошивках как отключённая заготовка
химреактора и не входит в HTTP API фаблаб-теплицы.

Открытие COM-порта означает доступность транспорта, но не подтверждает
ответ платы. `hub/probe` посылает get_temp(idx=3), ждёт INVALID_INDEX от
хаба и не затрагивает нижние узлы. Все прошивки должны быть совместимы с
новыми маршрутами node15/16; старый хаб с get_door_state на Arduino несовместим.
