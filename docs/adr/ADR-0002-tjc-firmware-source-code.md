# ADR-0002: Разрабатывать прошивки МС-ТЮК непосредственно на C++

## Status

Accepted — направление задано пользователем 2026-10-06; перенос прошивок ещё не выполнен.

## Context

В tjc-sketch транспортный обмен ранее описывался Cyberiada-GraphML-моделью и поддерживался генератором диаграммы. Новый аппаратный API требует изменения запросов, ответов и маршрутизации. Развитие через диаграмму добавляет промежуточный формат и зависит от возможностей графического представления.

Пользователь выбрал непосредственную разработку исходного кода, чтобы ускорить работу. Альтернатива — продолжить генерацию GraphML с последующим получением кода компилятором. Переход снимает зависимость разработки от диаграммы, но требует явно сопровождать точку входа, сборку и аппаратный runtime.

## Decision

Основными исходниками центральной МС-ТЮК платы и двух Arduino-шлюзов будут рукописные C++-файлы в tjc-sketch. GraphML не является источником новой реализации и не нужен в её обязательном пути сборки.

Настройки toolchain, startup, linker script и аппаратные библиотеки изучаются по соответствующим platforms/library в lapki-compiler. Старую GraphML-модель и пользовательские изменения сохраняем как исторические артефакты.

## Consequences

Транспортный код можно изменять непосредственно, не синхронизируя диаграмму и генератор. Теряется прежний путь визуального редактирования новой прошивки.

Нужно подготовить воспроизводимую сборку и проверить совместимость с загрузчиком, IRQ и аппаратными библиотеками. Состав QHSM-зависимостей определяется по фактическому рукописному коду и проверке сборки. Смена формата исходников не меняет распределение ответственности аппаратного API.

Результаты изучения и ссылки на зафиксированную ревизию upstream находятся в [TJC-FIRMWARE.md](../TJC-FIRMWARE.md).
