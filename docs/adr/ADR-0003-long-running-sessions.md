# ADR-0003: длительная работа без исчерпания номеров запросов

Дата: 2026-10-08. Принято по требованию пользователя.

Прежний v1 останавливался после 65535 запросов и 4096 решений. Для активно
используемой системы накопительные лимиты неприемлемы; ограничивать нужно
текущую очередь и память, не срок службы.

v2 сохраняет поля команд/data, добавляет 64-битную session_id перед CRC.
Кадр 28 байтов, версия 2, CRC покрывает 2..25. Ответ коррелируется по сессии,
tx_id, node, command и idx. При старте процесса сессия случайная ненулевая;
при wrap tx_id сессия увеличивается, номер снова 1. Активные/ожидающие запросы
хранят исходную пару. Повтор старого ответа не завершает новый запрос.
64-битные сессии не являются аутентификацией; случайное совпадение между
процессами крайне маловероятно, но не математически невозможно.

Журнал decision_id/аргументов/результатов хранится в SQLite. До постановки ID
резервируется синхронно; результат сохраняется перед возвратом клиенту.
RAM-кэш содержит 4096 завершённых решений; вытеснение не теряет дедупликацию.
После сбоя между резервированием и результатом повтор не исполняется: исход
неизвестен, нужно сверить физическое состояние. Exactly-once при потере питания
не обещается. Файл БД нужно сохранять и следить за свободным диском.

v1 и v2 несовместимы. Обновляются вместе сервер, хаб, оба шлюза и обе Arduino.
Автоматического fallback или повторов меняющих команд нет. Время ожидания
очереди, физические тайм-ауты и верхняя граница текущей FIFO не меняются.
